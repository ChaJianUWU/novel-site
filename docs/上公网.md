# 让别人能打开你的小说站

本机跑起来的 `http://127.0.0.1:8787` 只有自己这台电脑能访问。要让别人看到，有四条路，
按「省事 → 长期」排列，挑一条就行。

---

## 方案一：Serveo / Pinggy 隧道（最短路径，免费）

前提：网站已经在跑（`一键启动.bat` 的窗口别关）。

```bat
ssh -o StrictHostKeyChecking=no -o ServerAliveInterval=30 -R 80:localhost:8787 serveo.net
```

等几秒，窗口里出现 `Forwarding HTTP traffic from https://xxxx.serveo.net` —— 这个地址就是公网网址。
（`一键公网.bat` 双击的就是这条命令。）

想要**固定子域**（重启也不变），先登记一把密钥，只需一次：

```bat
ssh-keygen -t ed25519 -f %USERPROFILE%\.ssh\novel_site
type %USERPROFILE%\.ssh\novel_site.pub
```

把打印出来的公钥整行粘到 <https://console.serveo.net/>（或按页面提示提交），然后：

```bat
ssh -i %USERPROFILE%\.ssh\novel_site -o ServerAliveInterval=30 -R novelbook:80:localhost:8787 serveo.net
```

以后地址就一直是 `https://novelbook.serveousercontent.com`。

Pinggy 备用（换域名就换这一条）：

```bat
ssh -p 443 -o StrictHostKeyChecking=no -R0:localhost:8787 a.pinggy.io
```

**这条路的代价**：电脑必须开着、不能断网、隧道窗口不能关。电脑一关，网站下线。

## 方案二：cloudflared 快速隧道（免费，不用 ssh）

1. 下载 <https://github.com/cloudflare/cloudflared/releases/latest> 里的 `cloudflared-windows-amd64.exe`，
   改名 `cloudflared.exe` 放到 `D:\novel-site\` 下。
2. 在站点目录开一个 cmd：

   ```bat
   cloudflared.exe tunnel --url http://127.0.0.1:8787
   ```

3. 窗口里会打印一个 `https://xxx.trycloudflare.com`，发给别人即可。

优点是不用 ssh、不用账号；缺点是域名每次重启都变，而且部分网络（含国内一些运营商）可能打不开 `trycloudflare.com`。

## 方案三：便宜 VPS（长期在线，推荐真要用）

以 Ubuntu 22.04 为例，装 Node 18+ 之后：

```bash
sudo apt update && sudo apt install -y git curl
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
git clone https://github.com/ChaJianUWU/novel-site.git
cd novel-site
npm start          # 先手动跑一次，确认能起来
```

常驻（二选一）：

```bash
# 用 pm2
sudo npm i -g pm2
pm2 start server.mjs --name novel-site
pm2 save && pm2 startup

# 或者 systemd
sudo tee /etc/systemd/system/novel-site.service >/dev/null <<'EOF'
[Unit]
Description=novel site
After=network.target
[Service]
WorkingDirectory=/root/novel-site
ExecStart=/usr/bin/node server.mjs
Restart=always
Environment=PORT=8787
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl enable --now novel-site
```

再配 Nginx 反代 + 证书（Certbot 一键）：

```nginx
server {
  server_name your-domain.com;
  location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}
```

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

搬家/备份：把 `data/kv.json` 拷过去即可。

## 方案四：PaaS 平台（不想管服务器）

仓库里已经带了部署文件：`Dockerfile`、`render.yaml`、`Procfile`，Node 环境变量只有一个 `PORT`。

- 支持 Node 的平台：新建 Web Service → 连仓库 → Build `npm install`（其实零依赖）→ Start `npm start`。
- 部署完记得设置环境变量 `ADMIN_KEY`（自定义管理员密钥）和 `SYNC_KEY`，否则会随机生成，你找不到。
- 数据存在容器本地文件系统时，**重新部署会丢**。长期用请挂持久卷，或定期导出备份。

---

## 环境和变量对照表

| 变量 | 作用 | 不设会怎样 |
| --- | --- | --- |
| `PORT` | 监听端口 | 默认 8787 |
| `DATA_DIR` | 数据目录 | 默认 `./data` |
| `ADMIN_KEY` | 管理员密钥（进 `/admin`） | 自动生成，写入 `data/admin-key.txt` |
| `SYNC_KEY` | 批量同步接口用的密钥 | 自动生成，写入 `data/sync-key.txt` |
| `SITE_TITLE` | 站名 | 默认「小说站」 |

启动时终端会打印这几行，第一次启动记得抄下来。

## 上线前安全检查清单

- [ ] 管理员密钥不是默认值，自己改过
- [ ] `data/` 目录不要公开（不要放进静态托管、不要提交进公开仓库）
- [ ] 隧道/PaaS 的网址是 https
- [ ] 试过：别人投稿能成功、作者名空着会被拒绝、别人的书你改不动
- [ ] 备份一份 `data/kv.json`
